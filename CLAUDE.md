# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## What this is

A self-hosted manga/media organizer. `be/` is a FastAPI + SQLModel (SQLite) backend; `fe/` is a SvelteKit SPA (Svelte 5 runes, carbon-components-svelte). Production is a single Docker image (nginx + backend under supervisord, see `Dockerfile` and `compose.yaml`). The frontend is also deployed standalone to Vercel, where **mock mode** (`?mock=1`) is the demo/preview — it must work without any backend.

## Development model: CI is the quality gate

Development happens in cloud environments; correctness is enforced by automation, not manual testing. The rules:

1. **Backend: every feature ships with API-level tests.** `.github/workflows/be-ci.yml` runs `ruff check` and `pytest --cov=. --cov-fail-under=90` — the build fails below 90% coverage. New endpoints need tests for the success path and the error paths (404/400) in `be/tests/test_api_<router>.py`.
2. **Frontend: mock data must cover every backend feature the UI uses.** Any backend endpoint consumed by the frontend must have an MSW handler in `fe/src/lib/mock.ts`, with faker-generated data matching the real response schema exactly (same fields, same types as `fe/src/lib/client/types.gen.ts`). This is machine-enforced: `fe/src/lib/mock-parity.test.ts` statically extracts every endpoint the app consumes (SDK calls and raw `/api/...` URLs) and fails if `mock.ts` lacks a handler. It checks presence, not payload shape — keeping mock data schema-accurate is still on you.
3. **Frontend CI** (`.github/workflows/fe-ci.yml`) runs `npm run lint`, `npm run check`, `npx vitest run` (which includes the mock-parity test), and `npm run build`. Husky pre-commit hooks additionally run prettier + eslint on staged files.

## Commands

Backend (run from `be/`):

```bash
uv sync                                   # install deps
uv run pytest -q                          # full test suite
uv run pytest tests/test_api_comics.py::TestGetAll::test_empty   # single test
uv run pytest --cov=. --cov-report=term-missing --cov-fail-under=90  # what CI runs
uv run ruff check                         # lint (also a CI gate)
uv run uvicorn main:app --port 8001       # dev server (docs at /api/docs)
```

Frontend (run from `fe/`):

```bash
npm install
npm run dev          # vite dev server on port 8002
npm run check        # svelte-check (type errors)
npx vitest run       # unit tests
npm run lint         # prettier --check + eslint
npm run format       # prettier --write
npm run api          # regenerate the OpenAPI client (see below)
```

`fe/package-lock.json` resolves packages against the official `registry.npmjs.org` — keep it that way. If you regenerate it behind an npm mirror, rewrite the URLs back before committing (`sed -i 's|registry.npmmirror.com|registry.npmjs.org|g' package-lock.json`).

## Generated API client — never hand-edit

`fe/src/lib/client/*.gen.ts` is generated by `@hey-api/openapi-ts` from the running backend's OpenAPI schema. After any backend API change:

1. Start the backend on port 8001.
2. `cd fe && npm run api`
3. Revert the generated `baseUrl` change: `git checkout src/lib/client/client.gen.ts` (it must stay `baseUrl: ''`; the real URL is set at runtime by the connect flow).

## Backend architecture

- `main.py` wires class-based routers (`fastapi-utils` CBV) from `api/`. `comics`, `videos`, `system` routers get `require_auth` at include time; `comicpage` and `images` declare auth per-endpoint because browser `<img>` loads can't send headers — media endpoints accept `?token=` via `require_media_auth` (`core/auth.py`).
- Auth is a single `ADMIN_PASSWORD` env var; the token is a static HMAC of it. No users, no expiry. When `ADMIN_PASSWORD` is unset, auth is disabled (this is how tests run).
- `comicfile.py` abstracts comic sources (zip / rar / directory) behind one interface, with a small TTL cache around `create_open()`. Page order and filtering live in `order_pages()` (natural sort on the name without its extension, so `000.jpg` precedes `000-00.jpg`; image albums share the key). Records store cover and progress as page numbers, so changing the order means bumping `PAGE_ORDER_VERSION` and adding the old order to `pageorder.py`, which remaps them by page name (a job queued at startup when any record is outdated, plus inline on progress saves, set cover and cover runs). A folder comic is a folder without subfolders that holds page images only, like an image album (hidden files and `Thumbs.db`/`desktop.ini` aside, `non_page_files()`): a scan warns about and skips image folders with other files (e.g. archives moved in, so a record there shows as missing), and deleting a folder comic removes the folder only when it still qualifies, else just the record. Reading RAR needs an external decompressor: `rarfile` finds the official static 7-Zip the `Dockerfile` installs as `7zz` (Alpine's own `7zip` lacks the RAR codec, and bsdtar can't handle solid archives).
- Persistence is split: `ComicEntity` and `VideoEntity` are SQLModel tables (SQLite via `db.py`); **`ImageEntity` lives only in an in-memory dict** in `api/images.py`, rebuilt by `bootstrap()` on scan. Image albums are deliberately lightweight: no favorites or custom covers (the cover is page 0 served live; convert an album to a comic to keep it). Album ids are a hash of the folder path, so they are stable across scans. Each scan writes a JSON snapshot (`Config.image_snapshot_path`) that startup loads so the list isn't empty until the rescan finishes; reading progress is not persisted and is lost on restart.
- Covers are pre-generated JPEGs named `{id}_0.jpg` written to nginx-served directories (`global_data.Config.nginx_*_path`); the frontend loads them as static files from the same origin as the API (nginx serves `/api/` and the media/cover paths together; there is no separate static server). Cover URLs carry `entityUpdateTime` as a cache-busting version, so bump it whenever a cover file is rewritten. Admin → Covers (`covers.py`) regenerates them in the background (all, only missing ones, or only comics whose file changed in place — `changed` mode, one stat per comic: size or mtime differs from the record, folder comics by folder mtime; scans never re-check known paths), honoring `coverPosition`, refreshing page count, size and mtime, and deleting covers that can't be generated.
- `core/exceptions.py` maps request-validation errors to **400, not 422** — write test assertions accordingly.
- Background tasks live in `tasks/` and start from `core/lifespan.py`. Heavy jobs (media scans, cover runs) go through `core/jobs.py`: a single-lane queue (one job at a time, a job covered by a waiting one is skipped and one that covers waiting ones replaces them — a full scan covers single-type scans, a full cover run covers "missing"; in-memory history), exposed at `/api/system/jobs`; submit with `jobs.submit(kind, params)` (scans via `api.system.start_scan`), never start their threads directly. The database backup is light and stays outside the queue. Comic moves (`mover.py`, `POST /api/comics/move[/preview]`) are a queued job too: they update the record's `path` so id, favorite, progress and cover survive (a file moved outside the app is re-imported as a new comic), rename within a filesystem and copy-verify-delete across mounts (`EXDEV`), and refuse targets outside the comic scan folders or in the container's own filesystem. Folder comics and RARs become zips the same way (`zipper.py`, `GET/POST /api/comics/zip`, Admin → Convert to zip): a cancellable queued job that keeps the record, writing an uncompressed zip under a hidden name, checking every entry's size and CRC (a RAR is extracted once by `7zz` into a local temp folder and checked against its own file list; encrypted, multi-volume, linked or unsafe-named RARs are refused), renaming it into place and only then deleting the original; jobs report how far they got in `progress`. The suggested target (`/api/comics/move/suggest`, batched: one request for every row of the Move to folder table) is a folder named after the tag that already holds some of the comics, else `<COMIC_ARTIST_PATH or first scan path/artist>/<name>`; comic scans warn about scan/artist folders that aren't on a mounted drive. Scans (`loader.py`) import new paths only, after following moves (`_follow_moves`): a record whose file is gone takes over a new path with the same size and mtime (one-to-one only), and two records of the same file whose paths differ only in case/Unicode normalization (case-insensitive NTFS/SMB mounts) are merged into the older one, whichever spelling is present. Records are keyed by exact path (SQLite compares bytes), so moves write paths as the filesystem lists them (`mover.on_disk`). Scan phases (images, comics, videos) are isolated: one that raises is recorded and the others still run; the result is success/partial/error, and a partial or failed scan fails its job. Problems go to the scan status via `progress.add_issue(media, level, path, reason)` (`core/scan_progress.py`, shown in Admin): `skipped` for a file that can't be imported (`_to_entity` raises, e.g. `SkipFile`; retried on the next scan), `warning` for things that didn't stop anything (missing scan path, unreadable folder, no video cover), `error` for a failed phase.
- `ActivityEvent` (`model.py`) is an append-only log for stats, written via `events.py`. Only comics are logged so far: `add` on scan/import, `read` on progress saves (one row per item per day), `delete` on every delete including permanent ones. Filtered columns are flat; kind-specific fields go in the JSON `data` column. Record events in the same session as the change so they commit or roll back together.

## Backend test conventions

Fixtures in `be/tests/conftest.py`: `client` (TestClient with in-memory SQLite and patched nginx paths), `session`, helpers `insert_comic` / `insert_video`, and `MockComicfile` (fake archive; patch `comicfile.create_open` to avoid touching the filesystem). Page numbers are 1-based in the API and 0-based inside `Comicfile.read()`.

## Frontend architecture

- State modules use Svelte 5 runes in `*.svelte.ts` files (`config.svelte.ts`, `auth.svelte.ts`, `connection.svelte.ts`, `viewerState.svelte.ts`).
- The app is connection-gated: `ConnectDialog` either connects to a real backend URL (persisted in localStorage) or starts MSW mock mode via URL params `?mock=1` (`&auth=1` simulates login; mock password is `mock`), then stays on the page asked for. Mock data is seeded, so every start shows the same items.
- Navigation is real links (`<a href>`, `TagLink`, `FileCard href`), so middle-click works. Links that leave a page the user is working in (a tag's items from Tags or Folder, global search, item names in Stats/Admin/Duplicates, Move page links) open in a new tab: `target="_blank"` with `newTabHref()` from `lib/links.ts`, which adds the mock params in mock mode. Filtering within a page (list sidebar tags, search page tags, folder dirs) stays in the same tab.
- `routes/[mediaType=mediaType]/` serves comic/video/image lists from one route tree. Per-type API calls and capabilities live in `lib/mediaAdapters.ts` (`adapters[file.type].likePage(...)` etc.); don't pick an API service by hand in components. An optional adapter operation is absent when the type doesn't support it, and the UI shows the matching control only when it exists.
- The reader (`lib/components/FileContent.svelte`) is shared by comics and image albums.
- Tags are split from file names on the frontend (`separateFilename` in `lib/utility.ts`; comics by name, other media by path). Tag classification is manual: `TagInfo` (`api/tags.py`) stores only what the user decided — a kind (author / language / ignored) and aliases pointing at a primary tag (kept flat). `lib/tagIndex.ts` resolves aliases and counts a file once per primary tag; `lib/tags.svelte.ts` holds the session copy. The Classify view (`TagClassifier.svelte`) folds aliases into their primary's row (`classifierRows`) under every filter; expanding it splits an alias out or makes it the primary. Ignored tags are hidden from the sidebar and rankings, aliases match in the list search and gather into the primary's folder (Move to folder → Authors). Names the splitter reads wrong (unclosed, nested or stray brackets) are listed by `lib/nameCheck.ts` in Cleanup → Bad names (`/comic/cleanup`, which also holds Missing files), with a rename that previews the resulting tags. Cleanup → Normalize (`lib/normalizeName.ts`) bulk-renames names to half-width letters, digits and （）［］｛｝ (full-width symbols stay: ！？～ are deliberate in Japanese titles and ？：＊＂＜＞｜／＼ stand in for characters Windows forbids; 【】《》 have no half-width form), full-width katakana, single spaces and language-classified tags last; bad names are included since narrowing often fixes them, and a rename that would add a bracket problem is held back. Renames only refuse a path that's taken (same-named comics in other folders are fine) or a name with a path separator.
- The home page is one feed, `GET /api/home` (`api/home.py`): continue reading, recently added, favorites and random picks, each split by media type; `lib/home.ts` merges the types into one row per section. The reader opens at `?page=N` ("Continue reading" resumes there).
